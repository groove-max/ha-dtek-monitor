**Графіки відключень ДТЕК, особистий кабінет і передача показів — разом у Home Assistant.** Стежте за групами свого будинку, переглядайте споживання електроенергії та перевіряйте покази перед відправленням у ДТЕК.

<a id="features"></a>
## Що ви отримаєте

- Стан, причину та орієнтовний час завершення відключення, які ДТЕК повідомляє для адреси.
- Окремі календарі планових і можливих відключень.
- Вбудована [компактна картка добового графіка](docs/SCHEDULES.uk.md#compact-card) з вибором будинку у візуальному редакторі й автоматичним завантаженням.
- [Календар ремонтних робіт за адресою](docs/SCHEDULES.uk.md#address-works) з окремим станом для неповних або недоступних даних.
- Усі групи графіка, повернуті для адреси, зокрема для адрес із кількома групами.
- Окремо позначений **останній відомий графік** для перегляду, коли сервіс ДТЕК недоступний.
- Діагностику з’єднання, яка відрізняє помилку запиту від порожнього опублікованого графіка.
- Кілька адрес: для кожної додайте окремий запис інтеграції.

Стан адреси від ДТЕК **не є фізичним вимірюванням електроенергії у вашому помешканні**. Графік, поточне повідомлення оператора та показання локального лічильника — різні джерела інформації. Під час аварійних відключень опублікований графік може не діяти. Це незалежний проєкт спільноти, а не офіційний продукт ДТЕК.

<a id="regions"></a>
## Підтримувані оператори

Оберіть оператора системи розподілу, який обслуговує адресу, а не просто найближче місто.

| Територія | Оператор | Перевірка адреси |
| --- | --- | --- |
| Одеська область | ДТЕК Одеські електромережі — OEM | [Офіційна сторінка відключень](https://www.dtek-oem.com.ua/ua/shutdowns) |
| Київська область | ДТЕК Київські регіональні електромережі — KREM | [Офіційна сторінка відключень](https://www.dtek-krem.com.ua/ua/shutdowns) |
| Дніпропетровська область | ДТЕК Дніпровські електромережі — DNEM | [Офіційна сторінка відключень](https://www.dtek-dnem.com.ua/ua/shutdowns) |
| Місто Київ | ДТЕК Київські електромережі — KEM | [Офіційна сторінка відключень](https://www.dtek-kem.com.ua/ua/shutdowns) |

**Експериментальні регіони:** кабінети Київської та Дніпропетровської областей ввімкнено, включно зі входом, реєстрацією, керуванням рахунками, показами й визначенням групи квартири. Ці функції використовують спільний API, але ще не перевірені на реальних прив’язаних рахунках цих регіонів. Перед підтвердженням змін перевіряйте адресу, лічильник і тарифні зони. Повідомляйте про проблеми у [GitHub Issues](https://github.com/groove-max/ha-dtek-monitor/issues): зазначте оператора, версії HA та інтеграції, додайте знеособлену діагностику. Не додавайте паролі чи повні дані рахунку. Збій визначення групи не блокує дані лічильника.

У Києва та Київської області різні оператори. Для міста Києва майстер пропускає вибір населеного пункту. Навіть у підтримуваній області адресу може обслуговувати інший оператор: спочатку перевірте її на відповідному сайті. Інші оператори наразі не підтримуються.

<a id="installation"></a>
## Встановлення

Потрібні **Home Assistant 2026.3.0 або новіший** та доступ із Home Assistant до сайту обраного оператора ДТЕК. HACS спрощує встановлення, але не є обов’язковим.

### Через HACS

1. Відкрийте **HACS → ⋮ → Custom repositories**.
2. Додайте `https://github.com/groove-max/ha-dtek-monitor`, тип — **Integration**.
3. Знайдіть **DTEK Monitor** і завантажте [останній випуск](https://github.com/groove-max/ha-dtek-monitor/releases/latest). Перемикач попередніх версій не потрібен. [Інструкція оновлення](docs/UPGRADING.uk.md).
4. Перезапустіть Home Assistant.
5. Перейдіть до [адреси](#setup) або [особистого кабінету](#personal-account).

Це [користувацький репозиторій HACS](https://hacs.dev/docs/faq/custom_repositories/). Завантаження через HACS встановлює файли, але ще не налаштовує адресу.

Некомерційна ліцензія не відповідає вимогам загального каталогу HACS. Встановлюйте через **Custom repositories**, як описано вище.

### Вручну

1. Завантажте **dtek_monitor.zip** з [останнього випуску](https://github.com/groove-max/ha-dtek-monitor/releases/latest).
2. Розпакуйте архів у `custom_components/dtek_monitor` усередині каталогу конфігурації Home Assistant.
3. Переконайтеся, що отримали шлях `custom_components/dtek_monitor/manifest.json`, без зайвої вкладеної папки.
4. Перезапустіть Home Assistant і виконайте налаштування нижче.

<a id="setup"></a>
## Додавання адреси

1. Відкрийте **Налаштування → Пристрої та служби → Додати інтеграцію**.
2. Знайдіть **DTEK Monitor**.
3. Оберіть оператора, потім **Графіки за адресою**, населений пункт, вулицю та номер будинку. Використовуйте назви, які пропонує ДТЕК.
4. Для початку залиште інтервал опитування **300 секунд (5 хвилин)**.
5. Відкрийте створений пристрій і перевірте його сутності.

Згодом інтервал можна змінити через **Налаштувати** на картці інтеграції. Допустимий діапазон — 60–3600 секунд. Частіші запити не змушують ДТЕК швидше публікувати нові дані.

**Перша перевірка:** після успішного оновлення діагностика з’єднання має показувати `ok`. Порівняйте стан адреси з офіційним сайтом і додайте календар **Графік відключень** на панель Home Assistant. Порожній календар не завжди означає помилку: ДТЕК міг ще не опублікувати дані на обрану дату.

Для іншої адреси додайте ще один запис інтеграції. Редагувати `configuration.yaml` не потрібно.

<a id="personal-account"></a>
## Особистий кабінет і панель «Мій ДТЕК»

1. Додайте інтеграцію, оберіть свого оператора розподілу, потім **Особистий кабінет і покази**.
2. Увійдіть за телефоном і паролем. Також можна зареєструватися або відновити пароль через SMS.
3. Оберіть особові рахунки для моніторингу. Якщо кабінет порожній, додайте рахунок тут або пізніше в налаштуваннях.
4. Оновіть сторінку HA. На панелі оберіть **Редагувати → Додати картку → Мій ДТЕК**, оберіть рахунок і збережіть.
5. Перевірте прив’язку будинку. Однозначну адресу підключаємо автоматично; неточну треба підтвердити. Єдину підтверджену групу кабінету або єдину групу будинку обираємо автоматично. В інших випадках оберіть групу квартири в налаштуваннях. HA повідомляє про підтверджені зміни груп і автоматично замінює зниклу ручну групу, коли заміна однозначна. [Як працює вибір групи](docs/SCHEDULES.uk.md#section-2).

**Огляд** показує адресу, останні накопичувальні покази та окремо місячне
споживання. **Графік** містить сітку всіх груп із виділенням будинку та квартири,
список і збереження PNG. У **Показах** можна перевірити й передати значення,
у **Споживанні** — переглянути місячну історію. **Налаштування** містять дані
рахунку, EIC, лічильника, групу, датчик енергії та необов’язкові нагадування.

Для кількох квартир оберіть окремий рахунок на кожній картці або ввімкніть
перемикач рахунків. Вибір у картці не змінює інші панелі чи моніторинг HA.
Номер рахунку можна показати й сховати кнопкою ока.

Датчик енергії необов’язковий. Підходить не лише ATORCH: використовуйте
накопичувальний датчик міського споживання потрібної квартири. Прив’язка,
звірка з офіційним лічильником, поправки, перевірки за розкладом і нагадування
описані в [посібнику показів](docs/ENERGY_AND_READINGS.uk.md).
У формі показів HA також можна додати фото лічильника й перевірити їх перед підтвердженням передачі. Дивіться [інструкцію щодо фото](docs/ENERGY_AND_READINGS.uk.md#фото-лічильника).

**Автоматичної передачі показів немає** — кожне надсилання підтверджує адміністратор HA.

[Повне налаштування кабінету та можливості](docs/PERSONAL_ACCOUNT.uk.md).

**Мова:** підтримуються англійська та українська. Якщо в HA обрано російську, інтеграція використовує українську в налаштуванні, картках і сповіщеннях. Мова самого HA не змінюється.

<a id="data"></a>
## Як розуміти сутності

Назви залежать від мови Home Assistant. Фактичні ID дивіться на сторінці пристрою: після оновлення старої версії або ручного перейменування вони можуть відрізнятися.

| Сутність | Для чого потрібна |
| --- | --- |
| **Живлення (Power)** | `on` — ДТЕК не повідомляє про активне відключення; `off` — повідомляє. Це не вимірювання у вашій розетці. |
| **Статус / опис відключення** | Тип і причина за даними ДТЕК: норма, аварійне, планове або стабілізаційне відключення. |
| **Початок / завершення відключення** | Заявлений початок та орієнтовне завершення. За відсутності відключення порожні значення можуть бути нормальними. |
| **Основна група / Усі групи графіка** | Групи адреси. Перша група не обов’язково є єдиною. |
| **Останнє оновлення ДТЕК / Зміна графіка** | Час оновлення джерела, а не момент фактичного зникнення світла. |
| **Наступне планове / можливе відключення; Завершення за графіком** | Час подій для будинку або обраних груп квартири. [Значення й обмеження](docs/SCHEDULES.uk.md#upcoming-times). |
| **Доступність графіка на завтра** | Розрізняє опублікований графік, підтверджений порожній день, прогноз, неповні дані й помилки. |
| **Графік відключень** | Опубліковані планові інтервали. Наявність події не підтверджує фізичне відключення. |
| **Графік можливих відключень** | Можливі інтервали, якщо їх надає джерело; перетини з плановими прибираються. |
| **Останній відомий графік — лише перегляд** | Збережені події з часом перевірки. Для довідки, а не автоматичних сповіщень. |
| **З’єднання ДТЕК** | Діагностика доступності та актуальності, з окремими помилками адреси й графіка. |
| **Ремонтні роботи за адресою / Дані про ремонтні роботи** | Інтервали ремонтів, повідомлені оператором, та повнота даних. Окремо від графіків груп; завчасна публікація не гарантована. |

### Кілька груп і приховані номери

Якщо ДТЕК повертає кілька груп, інтеграція зберігає їх усі та позначає належність кожної календарної події. Без додаткової інформації вона не може визначити, до якої групи належить конкретний під’їзд або квартира.

Деякі оператори, зокрема в Києві, не публікують змістовних номерів груп. У HA можуть залишатися службові ідентифікатори. У будинковому режимі Telegram-бот показує їх як локальні **«Варіант 1», «Варіант 2»**. Це не офіційні номери черг; вони можуть змінюватися разом із прив’язкою адреси.

### Якщо графік недоступний

Після невдалої перевірки актуальні календарі стають недоступними. Інтеграція не видає старі дані за свіжі й не трактує неопублікований день як «відключень немає». Якщо не вдався лише запит графіка, сенсори стану адреси можуть продовжувати оновлюватися.

Підтверджена ДТЕК адреса може завершити перше налаштування без графіка.
Причина показана в сенсорі **Доступність графіка**; повторні спроби й відновлення автоматичні.

Окремий збережений календар доступний для перегляду, зокрема після перезапуску. Він містить конкретні події в межах восьмиденного періоду знімка: не вигадує неопубліковані дати й не повторює старий тижневий шаблон нескінченно. Докладніше: [актуальність і правила автоматизацій](docs/REFERENCE.uk.md#freshness).

<a id="troubleshooting"></a>
## Розв’язання проблем

| Симптом | Що перевірити |
| --- | --- |
| Інтеграції немає у списку додавання | Перезапустіть HA після встановлення; за ручного встановлення перевірте шлях папки. |
| Немає міста, вулиці чи будинку | Перевірте оператора й адресу на його сайті. Київ та Київська область — окремі варіанти. |
| Сенсори або актуальні календарі недоступні | Відкрийте діагностику з’єднання: `address_error`, `schedule_error`, час успішного оновлення. Повторні спроби виконуються автоматично. |
| Немає майбутніх подій | Перевірте, чи ДТЕК опублікував ці дати. Відсутність даних не підтверджує безперервного живлення. |
| ДТЕК показує наявність світла, але вдома темно | Інтеграція передає дані оператора. Для фізичного підтвердження використовуйте локальний датчик із [Telegram-ботом](https://github.com/groove-max/ha-dtek-telegram-bot/blob/main/README.uk.md#power-detection). |
| Не надходять повідомлення в Telegram | Їх надсилає окремо встановлений [DTEK Telegram Bot](https://github.com/groove-max/ha-dtek-telegram-bot/blob/main/README.uk.md). |

Тимчасова помилка сайту зазвичай не потребує видалення й повторного додавання адреси. Дивіться [діагностику та оновлення](docs/REFERENCE.uk.md#diagnostics).
