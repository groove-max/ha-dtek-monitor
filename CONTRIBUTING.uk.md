# Участь у розробці DTEK Monitor

[English](CONTRIBUTING.md) · **Українська** · [Посібник користувача](README.uk.md)

Повідомлення про помилки, виправлення та покращення документації можна подавати українською або англійською.

## Оберіть репозиторій

Обробка сайту ДТЕК, пошук адрес регіону та сутності HA належать до [DTEK Monitor](https://github.com/groove-max/ha-dtek-monitor). Доставка Telegram, шаблони та визначення живлення за локальними датчиками — до [DTEK Telegram Bot](https://github.com/groove-max/ha-dtek-telegram-bot).

Перед створенням issue перевірте наявні. Додайте версії, кроки відтворення, очікувану/фактичну поведінку й короткий журнал без приватних даних. Не публікуйте токени Telegram/HA, точні приватні адреси або робочі журнали цілком. Для вразливостей є [політика безпеки](SECURITY.uk.md).

## Запуск перевірок

Із кореня репозиторію, після встановлення зазначеної версії Python:

```bash
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -c "import json, subprocess, sys; subprocess.check_call([sys.executable, '-m', 'pip', 'install', *json.load(open('custom_components/dtek_monitor/manifest.json'))['requirements']])"
python -m unittest discover -s tests -v
python -m compileall custom_components tests
```

Без встановленого Home Assistant полегшений набір пропускає тести, що залежать від HA. Для повної перевірки створіть окреме середовище Python 3.14, встановіть `homeassistant==2026.3.0` і залежності manifest та повторіть запуск. Орієнтир — `.github/workflows/tests.yml`; не зараховуйте пропущені тести як успішні.

Зміни постачальника потребують фікстур опублікованих, неопублікованих, порожніх, некоректних і багатогрупових даних. Зберігайте ідентичність оператора/адреси й покриття публікації. Нові регіони додавайте через інтерфейс постачальника та явне ввімкнення, без регіональних умов у сутностях HA.

## Регіональні особисті кабінети

Публічні графіки (`providers.py`) та особисті кабінети (`account_providers.py`) вмикаються окремо. Графіки вже підтримують усіх чотирьох операторів нижче. Кабінети Одещини та Києва ввімкнено; Київщина та Дніпропетровщина ввімкнені експериментально й очікують перевірки на реальних рахунках.

| Оператор | Домен кабінету | Сучасний побутовий номер | Стан підтримки кабінету |
| --- | --- | --- | --- |
| Одеська область (`dtek_oem`) | `my.dtek-oem.com.ua` | 12 цифр, початок `572` | Увімкнено |
| Київ (`dtek_kem`) | `my.dtek-kem.com.ua` | 12 цифр, початок `452` | Увімкнено; читання даних перевірено наживо |
| Київська область (`dtek_krem`) | `my.dtek-krem.com.ua` | 12 цифр, початок `842` | Експериментально; очікує перевірки наживо |
| Дніпропетровська область (`dtek_dnem`) | `my.dtek-dnem.com.ua` | 12 цифр, початок `12` | Експериментально; очікує перевірки наживо |

`AccountProvider` у `account.py` визначає інтерфейс кабінету. `DTEKAccountClient` реалізує спільне API; `AccountProviderSpec` містить довірені домени, параметри OAuth, правила номера та прапорець увімкнення. Фабрика відхиляє вимкнених операторів до відкриття сесії. Кожен клієнт має власні cookies і токени та незмінну специфікацію регіону. Реєстрація/відновлення через SMS використовують ту саму специфікацію в окремій тимчасовій сесії. Якщо сервер потребує іншої поведінки, реалізуйте інтерфейс і виберіть реалізацію у фабриці, без регіональних умов у сутностях чи картках.

Публічний код сайтів, перевірений 19.10.2026, використовує спільний OAuth client ID та маршрути API: `/main-page/488.js` описує OAuth, `/main-page/602.js` — префікси сучасних рахунків. Ресурси доступні в кабінетах [Одещини](https://my.dtek-oem.com.ua/main-page/488.js), [Києва](https://my.dtek-kem.com.ua/main-page/488.js), [Київщини](https://my.dtek-krem.com.ua/main-page/488.js) та [Дніпропетровщини](https://my.dtek-dnem.com.ua/main-page/488.js). Однаковий код сайту не гарантує однакових даних і поведінки сервера після входу. Старі побутові номери Києва можна перетворити на сучасний номер рахунку. Інші старі формати та комерційні рахунки залишаються неперевіреними.

Перед увімкненням перевірте вхід або реєстрацію/відновлення, пошук і додавання рахунку, вибір рахунків, дані лічильника, прийняті покази, історію та зіставлення будинку на побутовому рахунку з дозволу власника. Готовий регіональний логін необов’язковий: із дозволу власника тестовий рахунок можна додати до нового кабінету. Перевірте, що вибір рахунку для HA не змінює його прив’язку в ДТЕК, а публічний будинок належить тому самому оператору. Реальну передачу показів погоджуйте окремо за фактичними значеннями лічильника; не надсилайте вигадані тестові покази. Додайте багатотарифні фікстури й зазначте, які тарифи перевірено наживо.

`test_account_regions.py` та `test_account_regions_runtime.py` перевіряють контракти зі штучними відповідями й тимчасово ввімкненими тестовими специфікаціями: домени/callback, номери, життєвий цикл SMS, ідентифікатори HA, повідомлення про зміни API та захист видалення рахунків. Тести не повинні вмикати неперевірені регіони у вихідному реєстрі. Особисті дані залишаються відокремленими від даних будинку, які використовує Telegram-бот.

Перевірки без авторизації 19.10.2026 підтвердили доступність сторінок входу, реєстрації й відновлення для чотирьох регіонів та вимогу авторизації в API рахунків. Також прочитано публічні довідники Києва, Київщини й Дніпропетровщини. Це не перевірка авторизованого кабінету. Повторювані назви вулиць, уточнення районів і корпуси не можна ігнорувати заради автоматичного збігу. Навігація використовує локальну відповідь `account_identity` із перевіркою прав (`provider_id`, `cabinet_url`); невідомий оператор не отримує посилання на інший кабінет.

## Перевірка на працюючій системі

Використовуйте окреме HA/тестове призначення та вимикайте робочу розсилку на час експериментів. Не перемикайте електричне обладнання як побічну дію програмного тесту. Вказуйте, які сценарії перевірені фікстурами, а які спостерігалися наживо.

## Документація та pull request

- Узгоджуйте `README.md` і `README.uk.md`; докладні посібники також мають версії `.uk.md`.
- README має допомагати встановити й використовувати проєкт. Контракти даних і подробиці коду належать до довідника та посібника розробника.
- Перевіряйте відносні посилання та YAML-приклади. Використовуйте умовні адреси й ID сутностей.
- Для зміни поведінки оновлюйте changelog; історичні записи випусків залишаються мовою оригіналу.
- Опишіть проблему, кінцеву поведінку та змістовні перевірки. Зберігайте параметри користувачів та ідентифікатори, якщо немає описаної міграції.
- Не додавайте до Git секрети, приватну діагностику, кеші, віртуальні середовища чи артефакти `graphify-out/`.

Надсилайте власні зміни або код, сумісний із [ліцензією проєкту](LICENSE). Внески подаються під PolyForm Noncommercial 1.0.0 зі збереженням повідомлень про права третіх сторін.

## Перевірка випуску

Запустіть тести HA на `2026.3.0` та `2026.10.2`, як у CI. Окремо встановіть Playwright 1.58.0 і Chromium та запустіть браузерні тести:

```sh
python -m unittest discover -s tests -p 'test_*card.py' -v
```

`python scripts/release.py v2.0.0-rc2` перевіряє версію, датовані примітки й канал публікації. У `.github/release-channel.json` задайте точну версію та булеве `prerelease`; невідповідність зупинить випуск. Для RC2 явно задано `false`, тому GitHub публікує звичайний випуск і позначає його Latest. Суфікс RC сам по собі не змінює цей вибір. CI публікує лише після всіх перевірок. Без файлу каналу суфікси alpha/beta/RC типово означають попередній випуск.

Локальна демонстрація — `examples/account-workspace/index.html`. Запустіть `python -m http.server 8974 --bind 127.0.0.1` з кореня репозиторію. Дані вигадані; екрани підключення є макетом і не надсилають SMS або показів.

Після зміни українських перекладів виконайте `python scripts/sync_translations.py`. Файл `ru.json` навмисно містить той самий український текст для російської мовної настройки HA; тест перевіряє синхронність цих файлів.

## Сайт документації

Посібники опубліковано [українською та англійською](https://groove-max.github.io/ha-dtek-monitor/).
Редагуйте наявні Markdown-файли, встановіть `website/requirements.txt` і запустіть
`python scripts/build_docs.py` та `python scripts/check_docs.py`.
[Інструкція підтримки сайту](website/README.md) описує збірку, попередній перегляд,
публікацію, зображення для посилань і перевірку Search Console. Сайт автоматично
оновлюється з `main`; згенерований HTML не додається в Git або архів інтеграції.
